## 1. Evaluation Philosophy: Structural Decomposition Before Ranking

Skill Arena does **NOT** throw diverse capabilities into a single monolithic leaderboard. Comparing a Three.js WebGL performance contract directly against a WCAG focus-ring accessibility rule or a Figma handoff workflow is an ontological category error.

The evaluation process operates in two discrete stages:
1. **Division Partitioning**: Grouping candidates into 9 orthogonal technical divisions.
2. **Design Knowledge Separation**: Strictly decoupling **Universal Design Engineering** from **Aesthetic Design Grammar** to prevent conflicting styling directives from corrupting core engineering laws.

## 2. Arena Divisions

Candidates are routed to one or more of nine specialized divisions. Participation across multiple divisions is permitted only where multi-domain claims exist:

### Division A: Web Engineering
- **Focus**: Core browser runtime mechanics, React architecture, state management, hydration, memory leaks, and DOM lifecycle.
- **Key Dimensions**: Runtime efficiency, strict typing, zero-leak disposal, bundle size minimization, and framework idiomaticity.
- **Historical Benchmarks**: B0 typecheck convergence, single-writer state coordination, zero-idle render loops.

### Division B: Design Engineering
- **Focus**: Semantic layout systems, responsive grids, fluid typography scales, accessibility trees, touch/keyboard interactions, and component composition.
- **Key Dimensions**: WCAG 2.1 AA compliance, ARIA semantic correctness, keyboard traversal, touch target sizes (`>=44x44px`), and layout stability (zero CLS).
- **Historical Benchmarks**: Ember & Root 4px/8px baseline grid, hairline architectural borders, Radix accessible dialogs.

### Division C: Visual Direction
- **Focus**: Visual hierarchy, aesthetic restraint, density calibration, typographic personality, surface elevation, and anti-generic visual identity.
- **Key Dimensions**: Restraint over ornamentation, visual clarity, intentional whitespace, absence of generic AI tropes (neon glow cards, purple gradients).
- **Historical Benchmarks**: O-TRAVELZ 4-tier typographic role model, Gravitas dark operational atelier.

### Division D: Motion
- **Focus**: Interaction micro-feedback, state transitions, physics models, scroll choreographies, and motion critique.
- **Key Dimensions**: Timing budgets (micro `<=120ms`, macro `<=320ms`), physics mass/damping (`cubic-bezier(0.16, 1, 0.3, 1)`), and strict reduced-motion adherence.
- **Historical Benchmarks**: Ember & Root reduced-motion contract, Hospitality-AAMA inertial camera transitions.

### Division E: Design References
- **Focus**: Passive design corpora, curated `DESIGN.md` guidelines, spatial interior/material studies, and reference URL libraries.
- **Key Dimensions**: Architectural coherence, material honesty, documentation quality, and non-prescriptive inspiration.
- **Historical Benchmarks**: `awesome-design-md`, Codrops interaction experiments, Hospitality-AAMA stone/lighting palettes.

### Division F: Component / Technique Sources
- **Focus**: Reusable UI component libraries, headless primitives, and snippet registries.
- **Key Dimensions**: Headless accessibility, zero unwanted CSS baggage, copy-paste modularity, and dependency footprints.
- **Historical Benchmarks**: shadcn/ui, Radix Primitives, React Bits, Skiper UI, 21st.dev.

### Division G: Workflow
- **Focus**: Designer-developer handoff, Figma-to-code, Stitch workflows, image-to-code prompt pipelines, and QA review protocols.
- **Key Dimensions**: Fidelity to intent, prompt token efficiency, multi-agent review rigor, and reproduction consistency.
- **Historical Benchmarks**: Taste screenshot-to-code rules, CodeRabbit PR review pipelines, GSD sync workflows.

### Division H: Platform
- **Focus**: Non-web target platforms: Native Android (Jetpack Compose), iOS/macOS (SwiftUI), and Desktop (Electron/Tauri).
- **Key Dimensions**: Platform HIG fidelity, window lifecycle, OS insets/decorations, background task contracts, and memory constraints.
- **Historical Benchmarks**: O-TRAVELZ Mobile v4 Compose edge-to-edge & SwiftUI MV, Gravitas Electron IPC isolation.

### Division I: Specialist
- **Focus**: Deep specialized verticals: Programmatic SEO, security penetration hardening, performance profiling, and regulatory compliance.
- **Key Dimensions**: Standards compliance, zero false positives, audit depth, and deterministic verification.
- **Historical Benchmarks**: Sherlock OSINT probes, Playwright accessibility audits, MetricKit production telemetry.

## 3. Design Knowledge Split: Universal Laws vs. Aesthetic Grammars

A catastrophic failure mode of AI design agents is the collision of contradictory style guides in prompt memory (e.g., an agent receiving "use high-contrast neon badges" and "use muted monochromatic borders" simultaneously).

To eliminate this collision, Skill Arena enforces a hard ontological boundary:

```
                           DESIGN KNOWLEDGE
                                   │
         ┌─────────────────────────┴─────────────────────────┐
         ▼                                                   ▼
UNIVERSAL DESIGN ENGINEERING                      AESTHETIC DESIGN GRAMMAR
(Permanent Global Baseline)                       (Mutually Exclusive Profiles)
• WCAG 2.1 AA Contrast (4.5:1 text, 3:1 UI)       • Typography Personality (Serif vs Sans vs Mono)
• High-contrast 2px focus ring with 2px offset   • Information Density (Compact vs Comfortable)
• Physical touch targets >= 44x44px               • Surface Language (Material vs Flat vs Glass)
• prefers-reduced-motion collapse to <=150ms      • Geometry (Sharp 0px vs Rounded 8px vs Pill)
• Fluid responsive layout (no horizontal scroll)  • Border Treatment (Hairline 1px vs Borderless)
• Semantic HTML5 & WAI-ARIA role structures       • Color Strategy (Monochrome vs Mineral vs Vivid)
• Zero-idle render loops & memory disposal        • Motion Intensity (Subtle vs Cinematic)
• Inline actionable error messaging               • Atmosphere (Atelier vs Operational vs Consumer)
```

### Invariant:
- **Universal Design Engineering** rules are assigned disposition `CANONICAL_GLOBAL` and load unconditionally across all web and frontend agents.
- **Aesthetic Design Grammar** rules are assigned disposition `OPTIONAL_PROFILE` and are encapsulated inside mutually exclusive Design Profiles. Agents load exactly **one** design profile per project.

## 4. Design Profile Model

Design Profiles represent coherent aesthetic worldviews. They are never hardcoded by guesswork; they are synthesized from historical project evidence and curated reference corpora.

### Profile Dimensions:
1. `typography`: Display font family, pairing rules, weight distributions, line-height scales.
2. `density`: Row heights, table padding, gutter widths (compact, standard, relaxed).
3. `spacing`: Baseline grid multipliers (4px/8px vs 6px/12px).
4. `surface`: Base background luminance, elevation layers, material textures, drop shadows.
5. `geometry`: Corner radii (0px sharp, 4px crisp, 12px softened, 9999px pill).
6. `colorStrategy`: Primary/accent distribution, dark-mode luminance floors, saturation restraint.
7. `motion`: Curve profiles (inertial, snappy, instant), duration ceilings, presence of entrance choreography.
8. `imagery`: Aspect ratios, treatment filters (duotone, desaturated, raw, editorial), border bounding.
9. `interaction`: Hover state elevation vs outline tint, active press depress depth.
10. `navigation`: Topbar vs sidebar rail vs floating plinth vs command palette first.
11. `informationHierarchy`: Header-dominant vs data-table dominant vs narrative card flow.

### Candidate Archetypes Derived from User Evidence:
- **`TECHNICAL_OPERATIONAL`**: (Derived from Gravitas Personal OS & Sherlock) Ultra-dense, dark canvas, hairline borders, monospace telemetry, zero decorative graphics, instant response.
- **`PREMIUM_EDITORIAL`**: (Derived from O-TRAVELZ & awesome-design-md) High-contrast serif/sans typography, generous white space, subtle mineral tints, hairline separators, restrained imagery.
- **`TACTILE_ARTIFACT`**: (Derived from Ember & Root) Physical materiality, object-first containers, subtle noise textures, warm muted palette, 80ms press feedback, calm micro-animations.
- **`SPATIAL_TECHNICAL`**: (Derived from Hospitality-AAMA & Algoryxz) 3D WebGL scene framing, grounded floor grids, anti-static access flooring, cable raceways, temperature-calibrated equipment lighting.
- **`CONSUMER_PRODUCT`**: (Standard modern web) Friendly rounded geometry, high legibility, accessible touch targets, clear call-to-action hierarchies.

## 5. Static Arena Evaluation: Roles & Epistemic Diversity

The first stage of evaluation is the **Static Arena**, requiring zero code generation or live deployment. Rule candidates are subjected to rigorous multi-perspective review across 12 independent scout roles:

| Scout Role | Primary Responsibility | Critical Challenge Question |
| :--- | :--- | :--- |
| `UTILITY_SCOUT` | Evaluates practical applicability | "Does this rule solve a real problem encountered in real code?" |
| `DUPLICATION_SCOUT`| Detects semantic duplicates | "Is this identical in intent to an existing rule under different wording?" |
| `CONFLICT_SCOUT` | Identifies contradictions | "Does adhering to this rule violate another approved standard?" |
| `CONTEXT_SCOUT` | Classifies scope and boundaries | "Should this be global, stack-specific, or profile-specific?" |
| `ENGINEERING_SCOUT`| Evaluates code quality & idioms | "Does this promote robust, maintainable, modern patterns?" |
| `ACCESSIBILITY_SCOUT`| Audits WCAG & keyboard safety | "Does this degrade accessibility for any assistive technology user?" |
| `SECURITY_SCOUT` | Audits trust and credential boundaries| "Could this instruction exfiltrate data or permit malicious execution?" |
| `DEPENDENCY_SCOUT`| Audits baggage and prerequisites | "Does this rule introduce unnecessary runtime dependencies?" |
| `MAINTENANCE_SCOUT`| Assesses obsolescence risk | "Will this pattern break when underlying frameworks update?" |
| `DESIGN_CRITIC` | Critiques visual sophistication | "Does this encourage generic, boring, or visually cluttered output?" |
| `REDUNDANCY_CRITIC`| Audits prompt token weight | "Can this rule be expressed in 10 tokens instead of 200?" |
| `SYNTHESIZER` | Reconciles findings into dispositions | "What is the minimal, strongest distillation of these findings?" |

### Absolute Invariant:
`ROLE != MODEL`. A single model instance may execute different role prompts, but authentic epistemic diversity requires running different model architectures across adversarial roles.

## 6. Multi-Model Diversity Architecture

To avoid "fake diversity" (spawning 5 identical agents executing the same prompt against the same LLM checkpoint), Skill Arena enforces a formal discovery and assignment protocol:

```typescript
export interface QualifiedExecutionSurface {
  surfaceId: string;             // e.g., "antigravity-native-pro", "claude-code-cli"
  modelIdentifier: string;       // Exact model: "gemini-3.8-flash", "claude-3-7-sonnet"
  provider: 'GOOGLE' | 'ANTHROPIC' | 'OPENAI' | 'LOCAL';
  gateway: 'IN_PROCESS' | 'LOCAL_CLI' | 'LOCAL_DAEMON';
  costEligibility: 'ZERO_SPEND_INCLUDED' | 'PAID_AUTHORIZED' | 'PAID_BLOCKED';
  qualificationState: 'QUALIFIED' | 'EXPERIMENTAL' | 'DISQUALIFIED';
  architectureClass: 'DENSE_REASONER' | 'FAST_STREAMER' | 'CODE_SPECIALIST';
}
```

### Surface Selection Rules:
1. **Dynamic Runtime Discovery**: At execution time, the Arena queries available surfaces via K1 and records exact identifiers. No hardcoded model names from human memory.
2. **Cost Boundary Gate**: Surfaces flagged `PAID_BLOCKED` or `UNKNOWN_COST` are strictly inaccessible (`AUTONOMOUS_INCREMENTAL_SPEND = 0`). Only `ZERO_SPEND_INCLUDED` or pre-authorized free tiers may execute.
3. **Epistemic Assignment Matrix**:
   - **Agent A (Engineering & Architecture Scout)**: Dispatched to deep reasoning model for structural dependency analysis.
   - **Agent B (Adversarial Critic & Security Scout)**: Dispatched to independent model architecture for hostile boundary probing (`criticModel != authorModel`).
   - **Agent C (Design Critic & Aesthetics Scout)**: Dispatched to visual/creative reasoning surface.
   - **Agent D (Redundancy & Duplication Scout)**: Dispatched to high-speed token/pattern matcher.
   - **Agent E (Synthesis & Reconciliation)**: Dispatched to neutral synthesizer agent.

### Diversity Metrics Captured per Trial:
- `MODEL_DIVERSITY`: Count of unique model architectures utilized.
- `ROLE_DIVERSITY`: Count of orthogonal evaluative roles active.
- `HARNESS_DIVERSITY`: Count of distinct execution gateways (in-process vs headless CLI).

## 7. Bounded Stopping Rules

To prevent infinite multi-agent debate or token exhaustion:

1. **Maximum Discussion Turns**: Static evaluation is capped at **3 refinement rounds** per candidate cluster.
2. **Objection Convergence**: If Round $N$ produces zero new unique objections compared to Round $N-1$, the discussion halts immediately.
3. **Stable Duplicate Clusters**: Duplication clustering stops when the union of duplicate IDs remains unchanged over two consecutive passes.
4. **Unresolvable Contradiction Escalation**: If two models maintain an irreconcilable conflict over two rounds:
   - If the conflict is stylistic $\rightarrow$ Automatic split into separate Design Profiles.
   - If the conflict is technical/safety $\rightarrow$ Tagged `ESCALATE_TO_HUMAN` and pushed to the Human Decision Ledger.
5. **Human Gate Termination**: The Arena always halts at `WAITING_FOR_HUMAN_DECISION`. It cannot autonomously alter canonical registries.
