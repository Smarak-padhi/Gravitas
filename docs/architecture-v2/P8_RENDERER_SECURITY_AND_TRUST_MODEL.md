## 1. Threat Vectors in the Visual Surface

The desktop visual renderer is exposed to external and untrusted data generated by LLMs, web scraping, git repositories, and external tool outputs. Wave P8 systematically models and defends against 20 visual threat vectors:

### Vector 1: Malicious HTML / Script Injection via Tool Outputs
- *Attack:* A worker agent executes a tool that fetches an untrusted web page containing `<script>fetch('/exfil')</script>` or `<img src=x onerror=alert(1)>`. The raw output is displayed in the task inspector terminal.
- *Defense:*
  1. Strict Content Security Policy (CSP) blocking `eval()` and inline scripts: `default-src 'none'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data: app:;`.
  2. All tool outputs rendered into DOM are sanitized via `DOMPurify` with an aggressive allowlist, or rendered inside non-executable `<pre>` / monospaced text nodes (`textContent = ...`).

### Vector 2: Shader Abuse & GPU Denial-of-Service
- *Attack:* A compromised dependency or corrupted scene definition injects infinite loops or complex branching into fragment shaders, freezing the Windows DWM and GPU driver.
- *Defense:*
  1. Three.js materials use fixed, pre-compiled built-in shader programs (`MeshStandardMaterial`, `MeshBasicMaterial`).
  2. User-provided custom shaders are strictly prohibited in the Living HQ world pipeline.
  3. Windows Timeout Detection and Recovery (TDR) automatically terminates hanging GPU contexts; GRAVITAS catches `webglcontextlost` and falls back cleanly to 2D SVG mode.

### Vector 3: Memory Exhaustion via Unbounded Entity Creation
- *Attack:* An errant or compromised agent loop spawns 100,000 synthetic tasks or avatars, exhausting host VRAM and triggering an OS Out-Of-Memory (OOM) kill.
- *Defense:*
  1. Renderer projection limits: The projection adapter applies a bounded capacity filter (`MAX_VISIBLE_PROJECTED_AGENTS`, `MAX_VISIBLE_DAG_NODES`).
  2. Virtualized lists (e.g. `react-window` / `@tanstack/virtual`) for execution logs and DAG tables ensure DOM node counts never exceed a bounded viewport budget ($< 500$ nodes).

### Vector 4: Clickjacking & Transparent Overlay Spoofing
- *Attack:* Malicious CSS or an overlay injection places an invisible `pointer-events: auto` button over the "Reject Task" button, redirecting the operator's mouse click to "Approve Dangerous Execution".
- *Defense:*
  1. Human approval modals render inside a dedicated top-level modal dialog (`z-index: 1000`) with a modal backdrop (`backdrop-filter`) that consumes and traps all mouse events.
  2. Two-phase verification: High-consequence approvals require explicit typed confirmation or a sliding hold-to-confirm gesture rather than a bare single click.

### Vector 5: The "Visual Lie" (Spoofed Approval or Green Status)
- *Attack:* A renderer-level bug, stale projection, or DOM tampering displays a task as verified green, prompting the user to deploy code when the verification suite actually failed in the Kernel.
- *Defense:*
  1. **Canonical Evidence Binding:** The approval modal displays the immutable SHA-256 evidence hash (`evidenceDigest: 0x8a4b...`) directly from Kernel storage.
  2. **Independent Kernel Verification:** When the user clicks "Approve", the Electron Main broker sends the signed decision to the Kernel. The Kernel independently re-verifies that the task's state in SQLite is `WAITING_APPROVAL` and that the evidence hash matches. If the visual state was desynchronized, the Kernel rejects the command with `ERR_STATE_DESYNCHRONIZATION`.

## 2. Sandbox Enforcement & Unprivileged Boundary

1. **Chromium Sandboxing (`sandbox: true`):**
   - The visual renderer executes within Chromium’s OS-level restricted token sandbox.
   - No direct access to Windows Win32 APIs, no direct filesystem access, no ability to spawn child processes directly.
2. **Context Isolation (`contextIsolation: true`):**
   - The renderer execution context is strictly isolated from the Electron preload script.
   - `window.gravitasAPI` is exposed strictly via `contextBridge.exposeInMainWorld()`.
   - Dynamic channel dispatching is prohibited; only a closed set of typed, validated methods are exposed.
3. **Node.js Integration Disabled (`nodeIntegration: false`):**
   - `require()`, `process`, `Buffer`, and Node native modules are absent from the visual window.

2. **Stale Projection Detection:**
   - Every state update carries a monotonic `epoch` number.
   - If no heartbeat is received from the Kernel for longer than the staleness threshold (e.g. $3000\,\text{ms}$ `[NON-NORMATIVE EXAMPLE: REQUIRES_K_PHASE_CALIBRATION]`), the visual world dims and displays a warning:
     $$\mathbf{[CONNECTION\ STALE\ —\ VISUAL\ STATE\ UNVERIFIED]}$$
   - Any attempt to interact with approval buttons while stale is disabled until synchronization is restored.
